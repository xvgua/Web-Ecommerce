## 二、数据库层缺口

### 2.1 `order` 表 — 缺少优惠券/折扣字段

当前字段：

```sql
total_amount  DECIMAL(10,2) NOT NULL    -- 商品金额合计（无折扣）
```

**需要新增：**

```sql
ALTER TABLE `order`
  ADD COLUMN `coupon_id`        BIGINT        DEFAULT NULL COMMENT '使用的优惠券ID(user_coupon.id)',
  ADD COLUMN `coupon_discount`  DECIMAL(10,2) DEFAULT 0.00 COMMENT '优惠券抵扣金额',
  ADD COLUMN `discount_amount`  DECIMAL(10,2) DEFAULT 0.00 COMMENT '商品级折扣金额（预留折扣功能）',
  ADD COLUMN `pay_amount`       DECIMAL(10,2) DEFAULT 0.00 COMMENT '实付金额 = total_amount - coupon_discount - discount_amount';
```

**说明：**
- `total_amount`：商品原价合计（保持不变，作为原始金额记录）
- `coupon_discount`：优惠券实际抵扣金额（满减券=固定金额；折扣券=原价×(1-折扣率)）
- `discount_amount`：预留商品级折扣（例如限时折扣、会员折扣等），当前阶段暂不使用，但提前建字段避免后续改表
- `pay_amount`：用户实际需要支付的金额，是支付页面的显示依据
- `coupon_id`：关联 `user_coupon.id`，用于追溯使用的优惠券

### 3.3 `CouponServiceImpl` — 需要重写

**文件：** `service/impl/CouponServiceImpl.java`

**核心逻辑新增：**

#### a) 优惠券适用范围校验

```java
/**
 * 检查优惠券是否适用于当前订单中的商品
 * scopeType=1: 通用券，所有商品可用
 * scopeType=2: 分类券，订单中至少有一个商品属于指定分类
 * scopeType=3: 单品券，订单中至少有一个商品在指定商品列表中
 */
private boolean isCouponApplicable(Coupon coupon, List<Long> productIds, List<Long> categoryIds) {
    if (coupon.getScopeType() == null || coupon.getScopeType() == 1) return true;
    if (coupon.getScopeIds() == null || coupon.getScopeIds().isEmpty()) return true;

    List<Long> scopeIdList = parseScopeIds(coupon.getScopeIds());
    if (coupon.getScopeType() == 2) {
        return categoryIds.stream().anyMatch(scopeIdList::contains);
    }
    if (coupon.getScopeType() == 3) {
        return productIds.stream().anyMatch(scopeIdList::contains);
    }
    return true;
}
```

#### b) 折扣金额计算

```java
/**
 * 满减券: discount = 固定金额
 * 折扣券: discount = orderAmount * (1 - coupon.discount)
 * 免邮券: discount = 0 (运费另计，当前系统无运费概念)
 */
public BigDecimal calculateDiscount(Long userCouponId, BigDecimal orderAmount) {
    UserCoupon uc = userCouponMapper.selectById(userCouponId);
    Coupon coupon = couponMapper.selectById(uc.getCouponId());

    if (orderAmount.compareTo(coupon.getMinAmount()) < 0) {
        throw new BusinessException("订单金额未达到优惠券使用门槛");
    }

    if (coupon.getType() == 1 || coupon.getType() == 3) {
        return coupon.getDiscount();  // 满减券金额 / 免邮券(0)
    } else if (coupon.getType() == 2) {
        return orderAmount.multiply(
            BigDecimal.ONE.subtract(coupon.getDiscount())
        ).setScale(2, RoundingMode.HALF_UP);  // 折扣券
    }
    return BigDecimal.ZERO;
}
```

#### c) 抢购时间校验

```java
// 大额券抢购时间校验
if (coupon.getIsLarge() == 1 && coupon.getGrabStartTime() != null) {
    LocalDateTime now = LocalDateTime.now();
    if (now.isBefore(coupon.getGrabStartTime())) {
        throw new BusinessException("抢购尚未开始");
    }
    if (coupon.getGrabEndTime() != null && now.isAfter(coupon.getGrabEndTime())) {
        throw new BusinessException("抢购已结束");
    }
}
```

### 3.4 `OrderServiceImpl.createOrder()` — 需要重大修改

**文件：** `service/impl/OrderServiceImpl.java`

**当前流程：**
```
1. 获取购物车商品 → 2. 计算 totalAmount = sum(price × qty) → 3. 创建订单
```

**修改后流程：**
```
1. 获取购物车商品
2. 计算 totalAmount = sum(price × qty)
3. 【新增】如果传入了 userCouponId:
   a. 校验优惠券归属（属于当前用户、未使用、未过期）
   b. 校验适用范围（scope_type + scope_ids vs 订单中的商品分类/ID）
   c. 校验使用门槛（minAmount vs totalAmount）
   d. 校验抢购时间（大额券）
   e. 计算 couponDiscount
   f. 计算 payAmount = totalAmount - couponDiscount
4. 创建订单（totalAmount + couponDiscount + payAmount 写入）
5. 【新增】标记优惠券已使用（更新 user_coupon.status=1, use_order_id, used_time）
6. 清除购物车已选项
```

## 五、商品级折扣功能 — 详细审查

> **用户需求**：商品本身也会有打折，应付金额 = 商品原价 - 商品折扣金额 - 优惠券折扣。
> 管理后台商品管理需显示折扣价格，用户首页/列表/详情需显示原价（划线）和折扣后价格。

### 5.1 当前状态——"假折扣"

商品详情页 `detail.vue` 第 32-34 行存在一个**虚假划线价**：

```typescript
// 当前代码（detail.vue）
const displayPrice = computed(() =>
  selectedSku.value?.price ?? product.value?.price ?? 0
)

// 模板中：
<span class="detail-info__price">{{ formatPrice(displayPrice) }}</span>
<span class="detail-info__original" v-if="displayPrice < 99999">
  {{ formatPrice(displayPrice * 1.2) }}   // ← 假的！原价 = 实际价格 × 1.2
</span>
```

这段代码将实际价格乘以 1.2 作为"原价"展示，纯粹是视觉效果，**不代表任何真实的折扣数据**。商品实体中根本没有折扣相关字段。

**需要替换为**：从后端返回真实的 `discountPrice`，有折扣时显示真实原价+折扣价，无折扣时不显示划线。

### 5.6 折扣与优惠券的关系

两者是独立的优惠维度，叠加规则为：

```
实付金额 = 商品合计（折扣后） - 优惠券抵扣

即: payAmount = sum(displayPrice × qty) - couponDiscount
```

优先级：**先折后券** —— 先在商品层面打折（`displayPrice`），再在订单层面用优惠券减免。

计算流程：
1. 遍历订单商品，每个商品取 `displayPrice`（有折扣=折扣价，无折扣=原价）
2. 汇总 `totalAmount = sum(displayPrice × qty)`（这是折后商品合计）
3. 计算优惠券折扣 `couponDiscount`（基于折后 `totalAmount` 判断是否达到 `minAmount` 门槛）
4. 最终 `payAmount = totalAmount - couponDiscount`

### 5.7 折扣时间生命周期

管理后台设置折扣时间段后，商品价格随时间自动切换：

```
                              discountStart          discountEnd
                                   |======================|
创建商品 ──────────────────────────→ 显示折扣价 ──────────→ 恢复原价
(无折扣)       (等待折扣开始)        (discountPrice)        (price)
displayPrice   displayPrice                               displayPrice
= price        = price                                    = price
hasDiscount    hasDiscount          hasDiscount            hasDiscount
= false        = false              = true                 = false
```

**后端判断逻辑**（查询时实时计算，不修改数据库中的 price 字段）：

```java
// ProductServiceImpl — 每次查询商品时执行
LocalDateTime now = LocalDateTime.now();
boolean isDiscountActive = product.getDiscountPrice() != null
    && (product.getDiscountStart() == null || !now.isBefore(product.getDiscountStart()))
    && (product.getDiscountEnd() == null || !now.isAfter(product.getDiscountEnd()));

product.setDisplayPrice(isDiscountActive ? product.getDiscountPrice() : product.getPrice());
product.setHasDiscount(isDiscountActive);
```

**四种场景：**

| discountStart | discountEnd | 行为 |
|---------------|-------------|------|
| NULL | NULL | 立即生效，永久折扣（只要 `discountPrice` 不为 NULL） |
| 未来时间 | 更晚时间 | 等待到达 `discountStart` 后才显示折扣价 |
| 过去/现在 | 未来时间 | 当前正在折扣中，到期自动恢复原价 |
| 过去/现在 | 过去时间 | 折扣已结束，`displayPrice = price` |

**设计要点：**
- **不修改 `price` 字段**：折扣价 `discountPrice` 是独立字段，`price` 始终保留原价
- **到期自动恢复**：时间超过 `discountEnd` 后，`hasDiscount` 自动变为 false，前端显示原价
- **无需定时任务**：折扣状态在每次查询时实时计算，不依赖 cron job
- **前端不判断时间**：前端仅读取后端返回的 `hasDiscount` 和 `displayPrice`，不自行计算时间逻辑

## 七、关键风险与注意事项

### 7.1 金额安全

- 优惠券抵扣金额**必须在后端计算**，前端试算仅用于展示
- 提交订单时后端重新计算折扣金额，**不信任前端传入的折扣金额**
- 折扣金额使用 `BigDecimal`，与现有金额体系一致

### 7.2 并发安全

- 优惠券"已使用"标记必须在订单创建事务内完成
- 防止一张优惠券被多个订单同时使用：
  ```java
  // 乐观锁更新 user_coupon
  UPDATE user_coupon SET status = 1, use_order_id = ?
  WHERE id = ? AND status = 0
  ```
  检查 affected rows = 1，否则抛异常

### 7.3 取消订单时的优惠券回滚

- 取消订单/退款时需要将优惠券状态恢复为"未使用"
- 如果优惠券已过期，状态改为"已过期"而非"未使用"

### 7.4 退款中的优惠券处理

- 当前 `refundOrder()` 将订单状态设为 `REFUNDING(5)`
- 如需完整退款，优惠券是否退还取决于业务规则
- 建议：退款时不退还优惠券（一般电商惯例），但取消订单时退还

### 7.5 大额券 + 折扣券叠加

- 优惠券互斥：一个订单只能使用一张优惠券
- 未来折扣功能上线后：先算商品折扣，再减优惠券
  - `payAmount = totalAmount - discountAmount - couponDiscount`

## 九、小结

当前系统的优惠券模块已完成"领券"环节（领取 + 领券中心展示），但**完全没有和订单/支付流程打通**。此外，**商品本身无折扣字段**，详情页的划线价是 `price * 1.2` 的假数据。

### 核心改动按优先级：

**P0 — 优惠券下单集成：**
1. **订单表 + 订单实体**新增优惠券/折扣/实付字段
2. **下单流程**增加优惠券校验、适用范围过滤、折扣计算、使用标记
3. **确认订单页 + 支付页**增加优惠券选择和费用明细展示
4. **管理员后台**新建优惠券管理 CRUD（列表页+表单页+侧边栏）

**P1 — 用户体验闭环：**
5. **我的优惠券页面**（未使用/已使用/已过期）+ 领券中心增强（倒计时/分类筛选/状态机）
6. **优惠券弹窗组件**（可复用到确认订单页）

**P2 — 商品级折扣：**
7. **product 表 + product_sku 表**新增 `discount_price` 字段
8. **管理后台商品表单**新增折扣价+折扣时间输入，列表修复价格列为空 bug
9. **ProductCard + 商品详情页**删除假折扣 `* 1.2`，改为真实折扣价展示（原价划线灰+折扣价红+折扣角标）
10. **下单时**使用折扣价 `displayPrice` 计算订单金额

### 金额计算公式：

```
displayPrice = hasDiscount ? discountPrice : price
totalAmount  = sum(displayPrice × qty)        ← 折后商品合计
couponDiscount = 满减券金额 | totalAmount×(1-折扣率) | 0
payAmount    = totalAmount - couponDiscount    ← 用户实付
```
