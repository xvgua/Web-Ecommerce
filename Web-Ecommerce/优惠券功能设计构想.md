## 二、对你系统的设计建议

### 2.1 核心定位

需求是**"像 couponsPop 弹窗那样展示优惠券列表，不需要商品推荐区域"**。因此核心组件为：

- **一个优惠券弹窗 / 领券中心页面**，作为用户领券的入口
- 触发入口放在：首页导航 / 用户菜单 / 商品详情 / 购物车（按优先级逐步加）

### 2.2 页面路由设计

```
/client/src/views/coupon/
  └── center.vue          # 领券中心主页面（独立页面）

或作为弹窗组件复用在多个页面：
/client/src/components/business/
  └── CouponModal.vue     # 优惠券弹窗（可在多处打开）
```

建议**先做独立页面**（`/coupons`），后续再封装成弹窗组件在其他页面使用。

### 2.3 优惠券数据模型

#### 后端实体

```java
// Coupon.java — 优惠券模板
id          BIGINT      主键
name        VARCHAR     券名称，如"满100减5"
type        TINYINT     类型: 1=满减券, 2=折扣券, 3=免邮券
discount    DECIMAL     优惠金额 / 折扣率
minAmount   DECIMAL     最低消费门槛（0=无门槛）
totalQty    INT         发行总量
remainQty   INT         剩余数量
startTime   DATETIME    有效期开始
endTime     DATETIME    有效期结束
status      TINYINT     1=启用, 0=停用
createTime  DATETIME

// UserCoupon.java — 用户领取记录
id          BIGINT
userId      BIGINT
couponId    BIGINT
status      TINYINT     0=未使用, 1=已使用, 2=已过期
usedTime    DATETIME
useOrderId  BIGINT      使用的订单ID
createTime  DATETIME
```

#### 前端 TypeScript 类型

```ts
// shared/types/coupon.ts
export interface Coupon {
  id: number
  name: string
  type: number        // 1=满减, 2=折扣, 3=免邮
  discount: number
  minAmount: number
  remainQty: number
  startTime: string
  endTime: string
  status: number
  received?: boolean   // 当前用户是否已领取
}

export interface UserCoupon {
  id: number
  userId: number
  couponId: number
  coupon: Coupon
  status: number       // 0=未使用, 1=已使用, 2=已过期
  usedTime?: string
}
```

### 2.5 券卡片核心设计要点

| 设计元素 | 参考值 | 说明 |
|---------|--------|------|
| 卡片宽度 | 自适应（栅格 2列/3列） | 桌面端建议 2~3 列 |
| 卡片背景 | 渐变红/粉/金 | 满减券红底、折扣券金底、免邮券绿底 |
| 金额数字 | `32px` 粗体，红色 `#ff0036` | 视觉焦点 |
| ¥ 符号 | `18px`，同色 | 紧贴金额左侧 |
| 使用门槛 | `14px`，深色 | "满X元可用" 或 "无门槛" |
| 券名称 | `16px` 粗体，深色 | 一行展示 |
| 有效期 | `12px`，灰色 `#909090` | 格式：有效期至 YYYY-MM-DD |
| 领取按钮 | 圆角 `8px`，右侧对齐 | 已领过变灰"已领取" |
| 左侧图标 | `72×72` 圆角区域 | 券类型图标或品牌 logo |
| 底部剩余量 | `12px` 红色 | "仅剩 X 张" + 进度条 |

### 2.6 交互流程

```
用户进入 /coupons
  → GET /api/coupons (分页，含用户领取状态)
    → 展示优惠券列表

点击"立即领取"
  → POST /api/coupons/:id/receive
    → 成功: 该券按钮变为"已领取" + toast 提示
    → 失败: toast 提示原因（已领完/已过期/已领取）

下单时使用优惠券（后续扩展）
  → 确认订单页选择可用优惠券
    → GET /api/coupons/user/available?amount={订单金额}
    → 选中后更新应付金额
```

### 2.7 API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/coupons` | 分页获取可领优惠券列表 |
| GET | `/api/coupons/{id}` | 优惠券详情 |
| POST | `/api/coupons/{id}/receive` | 用户领取优惠券 |
| GET | `/api/user/coupons` | 我的优惠券列表（含状态筛选） |
| GET | `/api/user/coupons/available` | 下单时可用的优惠券（按金额筛选） |

### 2.8 实现优先级

| 阶段 | 内容 | 涉及文件 |
|------|------|----------|
| **Phase 1** | 后端：Coupon / UserCoupon 实体 + CRUD + API | Entity, Mapper, Service, Controller |
| **Phase 2** | 前端：领券中心页面 + API 对接 | `views/coupon/center.vue`, `api/coupon.ts` |
| **Phase 3** | 前端：领券入口（首页/导航） + 路由 | router, home 页面 |
| **Phase 4** | 前端：下单时选择优惠券 | confirm.vue, order 相关 |
| **Phase 5** | 管理后台：优惠券管理（CRUD） | admin views |

## 三、小结

核心思路是：**参考 `couponsPopWrapper` 中 `cpItemWrapper` 的卡片式布局**（左侧图标 + 红色大金额 + 使用条件 + 有效期 + 右侧操作按钮），去掉商品推荐区域，做成独立领券中心页面。后续该卡片组件可复用到弹窗、下单页等场景。
