## 一、现有注册流程回顾

```
┌─────────────────────────────────────────────────────────┐
│ 前端 (register.vue)                                      │
│   form: { username, email, password, confirmPassword }   │
│   ↓ POST /api/auth/register                             │
│ 后端 (AuthController)                                    │
│   ↓ UserServiceImpl.register()                          │
│   1. 密码一致性校验                                       │
│   2. 用户名唯一性校验                                     │
│   3. 邮箱唯一性校验                                       │
│   4. BCrypt 加密密码                                      │
│   5. 入库                                                 │
│   ↓ 返回成功                                              │
│ 前端 → 跳转 /login，提示"注册成功，请登录"                  │
└─────────────────────────────────────────────────────────┘
```

**结论：** 当前注册流程无任何邮箱验证环节，用户可填入任意不归属于自己的邮箱地址完成注册。

5. 验证通过 → 删除该验证码（一次性使用）

### 2.8 后端 — 缺失的基础设施

**邮箱发送：项目中无任何邮件相关代码。**

检查结果：
- `application.yml` — 无 `spring.mail.*` 配置
- 无 `JavaMailSender` Bean
- 无 `MailService` / `EmailService` 类
- 无 SMTP 配置

**验证码存储：项目中无任何验证码存储机制。**

候选方案：

| 方案 | 优点 | 缺点 |
|------|------|------|
| **Redis**（推荐） | 原生 TTL 支持，自动过期 | 需额外部署 Redis |
| **数据库表** | 不需额外中间件 | 需定时清理过期数据，无原生 TTL |
| **内存 Map** | 零依赖 | 重启丢失，不可水平扩展 |

**推荐 Redis**：验证码天然具有"短期有效、过期自动清除"的特性，与 Redis 的 `SETEX` 完全匹配。

## 三、目标流程设计

```
┌──────────────────────────────────────────────────────────┐
│                 邮箱验证码注册流程（目标）                    │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  1. 用户填写：用户名 + 邮箱 + 密码 + 确认密码               │

│     └─ 前端 toast："验证码已发送至您的邮箱"                   │

│     ├─ POST /api/auth/register { ..., captcha }           │
│     │   ├─ 校验密码一致性                                   │
│     │   ├─ 校验验证码（从 Redis 取值比对）  ← 新增           │
│     │   ├─ 校验用户名唯一                                   │
│     │   ├─ 校验邮箱唯一                                     │
│     │   ├─ 删除已使用验证码  ← 新增                         │
│     │   ├─ BCrypt 加密 + 入库                               │
│     │   └─ 返回成功                                        │
│     └─ 前端 → 跳转 /login，提示"注册成功，请登录"             │
│                                                          │
```

## 五、技术规约

### 5.1 验证码规范

| 属性 | 规格 |
|------|------|
| 长度 | **6 位纯数字** |
| 字符集 | 0-9 |
| 有效期（TTL） | **5 分钟** |
| 发送频率限制 | 同一邮箱 **60 秒内仅可发送一次** |
| 一次性 | 验证通过后立即删除，**不可重复使用** |
| 存储 Key 格式 | `register:code:{email}` |

### 5.2 Redis Key 设计

```
Key:   register:code:user@example.com
Value: "384729"
TTL:   300000 (ms) = 5 分钟

Key:   register:cooldown:user@example.com
Value: "1"
TTL:   60000 (ms) = 60 秒（发送冷却）
```

### 5.3 SMTP 配置约定

- 使用 `spring-boot-starter-mail` 自动配置的 `JavaMailSender`
- 邮箱账号/密码从 `application.yml` 读取（不硬编码）
- 生产环境建议使用环境变量覆盖敏感信息
- 邮件内容：HTML 格式，含验证码 + 有效期提示

**application.yml 增加：**

```yaml
spring:
  mail:
    host: smtp.163.com           # 或其他 SMTP 服务商
    port: 465
    username: ${MAIL_USERNAME}   # 环境变量注入
    password: ${MAIL_PASSWORD}   # SMTP 授权码
    properties:
      mail.smtp.auth: true
      mail.smtp.ssl.enable: true
  data:
    redis:
      host: localhost
      port: 6379
```

### 5.4 安全规范

| 规则 | 说明 |
|------|------|
| 验证码不返回到前端 | `send-register-code` 接口仅返回成功/失败，**不返回验证码明文** |
| 发送冷却 | 同一邮箱 60s 内拒绝重复发送，防短信/邮件轰炸 |
| 验证次数限制 | 同一邮箱验证失败超过 5 次，验证码作废，需重新获取 |
| 注册前校验邮箱已发送验证码 | 若 Redis 中无对应 key，拒绝注册（防止跳过验证码环节） |
| 日志脱敏 | 日志中不打印验证码明文 |
