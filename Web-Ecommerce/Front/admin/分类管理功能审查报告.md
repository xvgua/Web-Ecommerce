## 二、后端现状逐项审查

### 2.1 数据模型 vs 淘宝逻辑

```sql
-- init.sql
CREATE TABLE category (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  name        VARCHAR(50)  NOT NULL,
  parent_id   BIGINT       DEFAULT 0 COMMENT '0=一级分类',
  sort_order  INT          DEFAULT 0,
  create_time DATETIME     DEFAULT CURRENT_TIMESTAMP
);
```

| 对比维度 | 淘宝需求 | 当前实现 | 状态 |
|----------|----------|----------|------|
| 层级支持 | 两级（一级 + 二级） | `parent_id` 自引用，理论上支持无限层级 | ✅ 超需满足 |
| 名称字段 | 有 | `name VARCHAR(50)` | ✅ |
| 排序字段 | 一级和二级各有顺序 | `sort_order INT` | ✅ |
| 层级数量约束 | 只有两级 | **无约束**，可创建三级/四级 | ⚠ 缺校验 |
| 一级数量约束 | 有一定上限 | **无约束** | ⚠ 缺校验 |

### 2.2 `getCategoryTree()` — 客户端接口

```java
// CategoryServiceImpl.java:27-42
public List<Category> getCategoryTree() {
    List<Category> all = categoryMapper.selectList(
            new LambdaQueryWrapper<Category>().orderByAsc(Category::getSortOrder));
    Map<Long, List<Category>> childrenMap = all.stream()
            .filter(c -> c.getParentId() != null && c.getParentId() > 0)
            .collect(Collectors.groupingBy(Category::getParentId));

    List<Category> roots = new ArrayList<>();
    for (Category c : all) {
        if (c.getParentId() == null || c.getParentId() == 0) {
            c.setChildren(childrenMap.getOrDefault(c.getId(), new ArrayList<>()));
            roots.add(c);
        }
    }
    return roots;
}
```

| 对比维度 | 淘宝需求 | 当前实现 | 状态 |
|----------|----------|----------|------|
| 返回结构 | 一级 + 二级树形 | 一级（roots）→ children（二级） | ✅ 匹配两级 |
| 三级分类 | 不需要 | 代码只给 root 设 children，三级数据即使存在也不返回 | ✅ 被动兼容 |
| 排序 | 一级和二级各自排序 | 全局 `ORDER BY sort_order`，根和子混合排序 | ⚠ 排序逻辑需修正 |

**排序逻辑问题：** 当前 SQL 是全局 `ORDER BY sort_order`，导致子分类和父分类在同一排序序列中。淘宝的排序是一级分类之间排序，二级分类在各自父级内部排序。建议改为：

```java
// 一级按 sort_order
// 二级按 sort_order（在 build tree 时对 children 排序）
children.sort(Comparator.comparing(Category::getSortOrder));
```

**影响评估：** 如果所有一级分类的 sortOrder 值都小于二级分类，当前行为不会出 bug。但一旦二级分类的 sortOrder 小于某个一级分类，顺序就会乱。这是一个**隐性逻辑缺陷**。

**需补充的后端校验：**

```java
public Category create(Category category) {
    // 1. 名称非空
    if (category.getName() == null || category.getName().isBlank()) {
        throw new BusinessException("分类名称不能为空");
    }
    // 2. parentId 为 0 或指向已存在的一级分类
    if (category.getParentId() != null && category.getParentId() > 0) {
        Category parent = categoryMapper.selectById(category.getParentId());
        if (parent == null) throw new BusinessException("上级分类不存在");
        // 3. 禁止三级：parent 的 parentId 必须为 0
        if (parent.getParentId() != null && parent.getParentId() > 0) {
            throw new BusinessException("仅支持两级分类，无法在二级分类下继续添加");
        }
    }
    // 4. 同级同名检查
    Long count = categoryMapper.selectCount(new LambdaQueryWrapper<Category>()
            .eq(Category::getParentId, category.getParentId() == null ? 0 : category.getParentId())
            .eq(Category::getName, category.getName()));
    if (count > 0) throw new BusinessException("同级下已存在同名分类");
    
    categoryMapper.insert(category);
    return category;
}
```

```java
public void delete(Long id) {
    // 1. 有子分类 → 禁止删除
    if (categoryMapper.selectCount(
            new LambdaQueryWrapper<Category>().eq(Category::getParentId, id)) > 0)
        throw new BusinessException("该分类下有子分类，无法删除");
    // 2. 有商品 → 禁止删除
    if (productMapper.selectCount(
            new LambdaQueryWrapper<Product>().eq(Product::getCategoryId, id)) > 0)
        throw new BusinessException("该分类下有商品，无法删除");
    categoryMapper.deleteById(id);
}
```

| 检查项 | 结论 |
|--------|------|
| 有子分类时禁止删除 | ✅ 已实现 |
| 有商品时禁止删除 | ✅ 已实现 |

### 2.4 排序功能审查

当前排序依赖 `sort_order` 字段：

- 新增时默认 0，无自动递增逻辑
- 修改时可手动改数字
- 无交换两个分类顺序的专用端点
- 全局排序而非同级排序（与 getCategoryTree 读端行为一致但设计不合理）

| 淘宝需求 | 当前实现 | 状态 |
|----------|----------|------|
| 一级之间可排序 | sortOrder 手动修改 | △ 可用但体验差 |
| 二级在同一父级下排序 | 同上 | △ |
| 新增时自动排到最后 | 默认 0，排到最前 | ⚠ 行为不符预期 |

## 三、问题汇总（按严重程度）

### 致命（阻塞业务流程）

无。后台 API 基础 CRUD 均可工作，不会崩溃或丢数据。

### 高（功能不完整）

1. **缺少层级校验** — 可创建三级/四级分类，与淘宝二级逻辑矛盾。虽然 `getCategoryTree()` 不返回三级，但数据会积压在 DB 中。
2. **缺少 parentId 合法性校验** — 可指向不存在的父级，产生悬空子分类。
3. **管理端新增/编辑无父级选择** — 前端未传 parentId，只能创建一级分类。

### 中（影响使用体验）

4. **排序为全局而非同级** — 一级和二级在同一个 sortOrder 序列中排序。
5. **管理端列表无层级展示** — 返回平铺 list，前端需自行构建树。
6. **新增时 sortOrder 默认 0** — 新分类跑到最前面而非最后面，不符合直觉。
7. **缺少更改顺序的专用操作** — 只能手动编辑数字。

### 低（边界情况）

8. **update 缺少存在性校验** — 修改不存在的分类静默无效果。
9. **无名称去重检查** — 同一父级下可出现两个同名分类。
10. **update 缺少循环引用保护** — 可把自己设为父级。

## 五、结论

**后端基础架构正确** — `parent_id` + `sort_order` 的模型设计完全适配淘宝二级分类逻辑，CRUD 骨架完整，删除保护到位。

**但校验层几乎为空** — Controller/Service 缺少输入校验、深度限制、parentId 合法性检查、循环引用保护等。这些校验是保证"数据只存在两级"的关键，而不仅仅是依赖前端展示层隐式过滤。

**核心差距：**
- 后端：缺校验，可写入脏数据
- 管理端前端：缺 parentId 输入，无法创建子分类

**建议修复量：** 后端 3 个方法加校验（≈60 行），前端 1 个页面加树形和 parentId 选择（≈80 行改动）。
