# 商品批量导入/导出 Excel — 需求澄清说明

> 编写日期：2026-06-04
> 状态：待用户确认

---

## 一、背景

当前管理后台商品管理页面仅支持单个商品的 CRUD 操作，缺少批量处理能力。运营人员在以下场景中效率低下：

- 需要将商品数据导出到 Excel 进行线下编辑或数据分析
- 有大量新商品需要一次性录入（如供应商提供的商品清单）
- 需要批量修改商品价格、库存等字段后重新导入

当前项目的商品管理现有能力：

| 已有能力 | 状态 | 可复用性 |
| -------- | ---- | -------- |
| 商品 CRUD（单个新增/编辑/删除） | 完整 | 导入时复用创建逻辑 |
| 规格 SKU 管理（CRUD + 上下架） | 完整 | — |
| 分类管理 | 完整 | 导入时需关联分类 |
| 商品列表分页查询 | 完整 | 导出时复用查询条件 |
| Apache POI / EasyExcel 依赖 | **未引入** | 需要新增依赖 |

## 二、需要澄清的核心问题

### Q1：导出范围

导出商品数据时，应该导出哪些商品？

**方案 A — 导出当前筛选结果**

- 根据当前搜索条件（关键词、分类、状态）导出符合条件的商品
- 优点：灵活，可按需导出
- 缺点：如果搜索结果为空，导出空文件

**方案 B — 导出全部商品**

- 点击导出直接导出数据库所有商品
- 优点：简单直接
- 缺点：数据量大时文件很大，无法按需导出

**方案 C — 支持筛选 + 全部（推荐）**

- 默认导出当前筛选结果
- 提供"导出全部"和"导出筛选结果"两个选项，或前端弹出确认框

### Q3：导入模式

导入 Excel 时，如何处理已存在的商品？

**方案 A — 仅新增（跳过已存在的）**

- 根据商品ID或商品名称判断是否已存在
- 已存在则跳过该行，仅插入新商品
- 优点：安全，不会误覆盖
- 缺点：无法批量更新

**方案 B — 覆盖更新**

- 已存在的按ID覆盖更新
- 不存在的新增
- 优点：支持批量修改
- 缺点：可能误覆盖

**方案 C — 新增 + 覆盖混合（推荐）**

- Excel 中有 ID 的行 → 覆盖更新
- Excel 中无 ID（或 ID 为空）的行 → 新增
- 优点：灵活，同时支持新增和更新
- 缺点：需明确标识每行的操作意图

> **请选择：** 导入时如何处理已有商品？

### Q4：模板文件

是否需要提供下载商品导入模板？

**方案 A — 提供模板下载**

- 管理后台有"下载模板"按钮
- 模板包含表头行 + 示例数据行 + 分类对照表
- 优点：降低用户填写错误
- 缺点：需额外维护模板

**方案 B — 不提供模板**

- 直接上传任意 Excel，解析表头匹配字段
- 优点：简单
- 缺点：用户可能不知道格式要求

**方案 C — 导出即模板**

- 先导出一个已有的商品 Excel 作为模板参考
- 用户按格式填写后上传
- 优点：零维护成本，导出格式即导入格式

> **请选择：** 是否需要下载模板？模板格式如何？

### Q5：Excel 格式

Excel 文件对用户有哪些约束？

**方案 A — 严格校验**

- 固定表头顺序和列数
- 单元格格式不对直接报错拒绝导入
- 优点：数据质量高
- 缺点：用户体验差，容易因格式问题失败

**方案 B — 宽松匹配（推荐）**

- 按表头名称匹配字段（不依赖列顺序）
- 对空值、格式错误做容错处理
- 返回详细的错误报告（哪一行哪个字段有问题）
- 优点：用户体验好
- 缺点：实现稍复杂

**方案 C — 完全宽松**

- 跳过所有错误行，仅导入正确的
- 最后汇报成功/失败数量
- 优点：最大容错
- 缺点：用户可能不知道哪些没导入成功

### Q8：SKU 导入策略

导入商品时，SKU（规格）如何处理？

**方案 A — 不导入 SKU**

- 仅导入商品基本信息（名称、价格、库存、分类等）
- SKU 信息需要进入编辑页手动添加
- 优点：简单，避免 Excel 结构复杂化

**方案 B — 单行包含 SKU（扁平化）**

- 一行 = 商品基本信息 + 一个 SKU
- 多个 SKU 写多行（商品名相同时合并到同一商品下）
- 优点：一个 Sheet 搞定
- 缺点：表结构不直观

**方案 C — 双 Sheet（商品 + SKU 分开）**

- Sheet1：商品基本信息
- Sheet2：SKU 明细（关联商品名称或ID）
- 优点：结构清晰
- 缺点：用户操作较复杂

### Q9：技术选型

Excel 操作使用哪个 Java 库？

| 方案 | 优点 | 缺点 |
| ---- | ---- | ---- |
| A. **Apache POI** | 功能全面、社区成熟 | API 较底层、代码量大、内存占用高 |
| B. **EasyExcel**（推荐）| 阿里开源、注解驱动、内存占用低、读写快 | 依赖版本需注意兼容性 |

> **请选择：** 建议 B（EasyExcel），与 Spring Boot 集成最方便。

## 三、建议的最小可行方案（MVP）

综合考虑实现成本和实用性，建议以下 MVP 范围：

### 后端

1. 引入 **EasyExcel** 依赖
2. 新增 `ProductExcelDTO`（Excel 行数据模型，含 EasyExcel 注解）
3. 改造 `AdminProductController`：
   - `GET /api/admin/products/export` — 导出 Excel（支持筛选条件）
   - `POST /api/admin/products/import` — 导入 Excel
4. `ProductService` 新增 `exportProducts(query)` 和 `importProducts(file)` 方法
5. 导入逻辑：按 ID 判断新增/更新，按表头名称匹配字段，返回错误报告

### 前端（管理后台）

1. 商品管理页工具栏增加"导出Excel"和"导入Excel"按钮
2. 导出：调用后端接口下载文件
3. 导入：上传对话框 → 选择文件 → 上传 → 显示结果弹窗（成功/失败统计）
4. 可选：提供模板下载链接

### 不纳入 MVP

- SKU 导入/导出（仅导出/导入商品基本信息）
- 异步导入 + 站内通知
- 导入操作日志
- Excel 模板自动生成
