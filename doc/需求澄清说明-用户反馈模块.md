## 一、背景

当前项目中，客服聊天系统已经实现（用户可通过浮动按钮发起实时聊天），但缺少**异步反馈渠道**：用户无法在离开网站后提交系统问题、功能建议或体验意见。客服聊天是"即时沟通"，反馈系统是"留言式"的补充——用户不需要等待客服在线，可以随时提交，管理员稍后处理。

| 已有能力             | 状态       | 说明                                                                    |
| -------------------- | ---------- | ----------------------------------------------------------------------- |
| 客服聊天系统         | 已完整实现 | 浮动按钮 → 聊天面板，支持快捷回复、商品卡片，管理后台可查看/回复        |
| 个人中心页面         | 已完整实现 | 左侧导航：个人信息、收货地址、修改密码                                  |
| 管理后台 system 模块 | 仅有骨架   | `system/` 目录下仅有 `banner.vue`、`announcement.vue`，反馈页面尚未实现 |
| 用户反馈功能         | **不存在** | 表中无 `feedback` 表，无相关前后端代码                                  |

**核心诉求**：在个人中心新增"用户反馈"入口，用户可以提交问题反馈或功能建议，管理员在后台统一查看并处理。

### Q2：反馈表单内容

用户填写反馈时，需要哪些字段？

**方案 A — 极简表单**

- 反馈类型（下拉选择）+ 反馈内容（文本框）
- 优点：填写门槛低，提交率高
- 缺点：信息量少，管理员难以定位问题

**方案 B — 标准表单（推荐）**

- 反馈类型（下拉选择）
- 反馈标题（输入框，必填）
- 反馈内容（文本域，必填，500 字以内）
- 联系方式（选填，邮箱/手机，默认取当前用户邮箱）
- 截图上传（选填，最多 3 张，每张 ≤ 2MB）
- 优点：信息完整、可追溯，截图帮助定位问题
- 缺点：字段较多

**方案 C — 完整表单**

- 在方案 B 基础上增加：反馈来源页面 URL（自动获取）、浏览器信息（User-Agent）、严重程度（低/中/高/紧急）
- 优点：极度完整，适合大型产品
- 缺点：字段过多，用户体验重

### Q3：反馈提交后流程

用户提交反馈后，系统如何处理？

**方案 A — 仅存储（无管理员处理）**

- 反馈写入数据库，管理员在后台查看，不做状态变更
- 优点：实现最简单
- 缺点：用户看不到处理进度，无法闭环

**方案 B — 管理员处理 + 用户可见状态（推荐）**

- 反馈状态流转：待处理 → 处理中 → 已解决 / 已关闭
- 管理员可更新状态、填写回复内容
- 用户在个人中心可查看所有反馈及处理结果
- 优点：流程闭环，用户体验好
- 缺点：需管理后台开发处理功能

**方案 C — 管理员回复式（类似工单）**

- 管理员可多次回复、用户可追问，形成对话
- 优点：交互最深
- 缺点：实现复杂度最高，接近客服系统

### Q4：反馈列表 — 用户端展示

用户在个人中心的反馈列表应该如何设计？

**方案 A — 简单列表**

- 显示：标题、类型、状态、提交时间
- 点击展开详情（内容 + 管理员回复）
- 优点：实现简单
- 缺点：列表信息密度低

**方案 B — 卡片式列表（推荐）**

- 每条反馈一张卡片：类型标签、标题、状态标签、内容摘要（截断 100 字）、提交时间
- 点击进入反馈详情页（完整内容 + 管理员回复 + 状态时间线）
- 优点：视觉清晰，信息密度适中
- 缺点：需要独立详情页

**方案 C — 表格列表**

- 类似管理后台的表格：多列、分页、筛选
- 优点：信息密度高
- 缺点：移动端体验差，对消费者不友好

### Q6：通知机制

反馈状态更新时，是否需要通知用户？

**方案 A — 无需通知**

- 用户自行在个人中心查看反馈进度
- 优点：零开发成本
- 缺点：用户无法及时获知处理结果

**方案 B — 站内通知**

- 导航栏增加"消息通知"入口（红点/角标提示）
- 反馈状态变更时站内通知
- 优点：实时性好，无需额外基础设施
- 缺点：需开发站内通知系统

**方案 C — 邮件通知**

- 管理员回复/状态变更时发送邮件到用户邮箱
- 优点：用户离站也能收到
- 缺点：依赖邮件服务（项目已有 SMTP 配置）

**方案 D — 站内通知 + 邮件通知（推荐）**

- 两者结合
- 优点：覆盖最全
- 缺点：开发量最大

## 三、建议的最小可行方案（MVP）

综合考虑实验要求和实现成本，建议以下 MVP 范围：

### 后端

1. 新建 `feedback` 表（类型、标题、内容、截图、状态、回复、用户ID）
2. 新增 `Feedback` 实体、`FeedbackMapper`、`FeedbackService`
3. 新增 `FeedbackController`（用户端：提交反馈、查看我的反馈列表、查看反馈详情）
4. 新增 `AdminFeedbackController`（管理后台：反馈列表、查看详情、更新状态、填写回复）

### 前端 — 客户端

1. 在 `profile.vue` 左侧导航新增"用户反馈"入口
2. 新建反馈列表组件（卡片式列表，展示标题/类型/状态/时间）
3. 新建反馈提交表单（弹窗或独立页面）
4. 新建反馈详情页（查看完整内容 + 管理员回复 + 状态时间线）

### 前端 — 管理后台

1. 新建反馈管理页（列表 + 类型/状态筛选 + 分页）
2. 反馈详情弹窗（查看内容/截图 + 更新状态 + 填写回复）

### 不纳入 MVP

- 邮件/站内通知
- 满意度评分
- 批量操作
- 反馈数据统计 Dashboard
- 截图上传（保留字段，MVP 阶段仅文本反馈）
