## 一、状态机设计

```
                       ┌── 管理员拒绝 ──→ REJECTED (2) [终态]
                       │
用户提交申请 ──→ PENDING_REVIEW (0)
                       │
                       ├── 用户撤销 ──→ CANCELLED (6) [终态]
                       │
                       └── 审核通过 ──→ PROCESSING (1)
                                           │
                                           ├── 仅退款 ──→ COMPLETED (3) [终态]
                                           │
                                           └── 退货退款 ──→ WAITING_RETURN (4)
                                                               │
                                              用户填写退货物流  │
                                                               ↓
                                                    RETURN_SHIPPED (5)
                                                               │
                                              管理员确认收货    │
                                                               ↓
                                                       COMPLETED (3) [终态]
```

**条件自动审核规则（Q5 → C）：**

- 订单状态为"待发货(1)" → 提交后自动跳过 PENDING_REVIEW，直接进入 PROCESSING(1)
- 订单状态为"待收货(2)"或"已完成(3)" → 进入 PENDING_REVIEW(0)，等待管理员审核

**Order.status 与 refund_status 的关系：**

- 退款申请提交后，`order.status` 保持原值不变，用 `refund_status` 追踪退款流程
- 退款进入 PROCESSING(1) 时，`order.status` 改为 `REFUNDING(5)`
- 退款完成时，新增 `order.status = REFUNDED(6)`

### 3.2 详细接口设计

#### 客户端接口

##### POST `/api/orders/{id}/refund/apply` — 提交退款申请

```
Request:
{
  "refundType": 1,            // 1=仅退款, 2=退货退款
  "refundReason": "dont_want", // 退款原因枚举
  "refundDesc": "不想要了...",  // 补充说明(选填)
  "itemIds": [101, 102]        // 要退款的 order_item ID 列表
}

Response: { code: 0, message: "success" }
```

逻辑：

1. 校验订单归属 + 状态（1/2/3 可申请）
2. 校验 itemIds 均属该订单
3. 计算退款金额 = sum(item.price \* item.quantity)
4. 未发货(1) → refund_status = 1 (PROCESSING)，order.status = 5 (REFUNDING)，恢复库存
5. 已发货(2)/已收货(3) → refund_status = 0 (PENDING_REVIEW)，等待审核
6. 写入 refund\_\* 字段

##### GET `/api/orders/{id}/refund` — 获取退款详情

```
Response:
{
  code: 0,
  data: {
    orderId: 1,

    refundReasonText: "不想要了",

```

##### PUT `/api/orders/{id}/refund/cancel` — 撤销退款申请

仅 refund_status = 0 (待审核) 时可撤销。

```
Request:

  "company": "顺丰速运",
  "logisticsNo": "SF1234567890"

```

#### 管理后台接口

##### GET `/api/admin/refunds` — 退款申请列表

```
Query: page, pageSize, refundStatus, keyword(订单号)
Response: PageResult<Order>, 筛选有退款申请的订单
```

##### GET `/api/admin/refunds/{orderId}` — 退款详情

同客户端 `GET /api/orders/{id}/refund`，但不校验用户归属。

##### PUT `/api/admin/refunds/{orderId}/audit` — 审核退款

```
Request:
{
  "approved": true,           // true=通过, false=拒绝
  "rejectReason": "凭证不足"   // 拒绝时必填
}
```

逻辑：

- 通过：refund_status → 1 (PROCESSING)，order.status → 5 (REFUNDING)，恢复库存
- 拒绝：refund_status → 2 (REJECTED)，写入拒绝原因

##### PUT `/api/admin/refunds/{orderId}/confirm-return` — 确认退货收货

仅 refund_status = 5 (退货中) 时可操作。
操作后：refund_status → 3 (COMPLETED)，order.status → 6 (REFUNDED)

### 3.3 Service 核心逻辑伪代码

```java
// OrderServiceImpl.refundOrder - 提交退款申请
public void refundOrder(Long userId, Long id, RefundApplyRequest req) {
    Order order = 校验订单归属 + 状态(1/2/3);
    校验 itemIds 均属该订单;

    BigDecimal refundAmount = 计算选中商品总价;

    order.setRefundType(req.getRefundType());
    order.setRefundReason(req.getRefundReason());
    order.setRefundDesc(req.getRefundDesc());
    order.setRefundAmount(refundAmount);
    order.setRefundItemIds(toJson(req.getItemIds()));
    order.setRefundApplyTime(LocalDateTime.now());

    if (order.getStatus() == OrderStatus.PENDING_SHIP) {
        // 未发货：自动通过
        order.setRefundStatus(RefundStatus.PROCESSING);
        order.setStatus(OrderStatus.REFUNDING);
        restoreStock(order);  // 仅退选中商品
    } else {
        // 已发货/已收货：待审核
        order.setRefundStatus(RefundStatus.PENDING_REVIEW);
    }

    orderMapper.updateById(order);
}

// OrderServiceImpl.auditRefund - 管理员审核
public void auditRefund(Long orderId, RefundAuditRequest req) {
    Order order = orderMapper.selectById(orderId);
    校验 refund_status == 0 (待审核);

    if (req.getApproved()) {
        order.setRefundStatus(RefundStatus.PROCESSING);
        order.setStatus(OrderStatus.REFUNDING);
        restoreStock(order);  // 恢复选中商品库存
    } else {
        order.setRefundStatus(RefundStatus.REJECTED);
        order.setRefundRejectReason(req.getRejectReason());
    }
    order.setRefundDealTime(LocalDateTime.now());
    orderMapper.updateById(order);
}
```

**注意：`restoreStock` 需改造，仅恢复 `refund_item_ids` 中勾选的商品库存，而非整单恢复。**

## 九、边界情况与约束

| 场景                   | 处理方式                                |
| ---------------------- | --------------------------------------- |
| 已取消/已退款订单      | 不显示"申请退款"按钮                    |
| 已有退款申请的订单     | 显示"查看退款"，不重复申请              |
| 被拒绝后可重新申请     | refund_status=6(已撤销)时显示"再次申请" |
| 待审核时可撤销         | 提供"撤销申请"按钮，状态→6              |
| 退款金额不能超过实付   | 前端自动计算 + 后端校验                 |
| 退款商品必须属于该订单 | 后端校验 itemIds                        |
| 自动审核(未发货)       | 直接进入处理中，跳过PENDING_REVIEW      |
| 秒杀订单退款           | 走正常退款流程，秒杀库存不额外恢复      |
| 已使用的优惠券         | 不退（Q8选择A）                         |
