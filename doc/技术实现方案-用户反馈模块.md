## 一、状态机设计

```
用户提交反馈 ──→ PENDING (0) 待处理
                    │
                    ├── 管理员开始处理 ──→ PROCESSING (1) 处理中
                    │                          │
                    │                          ├── 解决完成 ──→ RESOLVED (2) 已解决 [终态]
                    │                          │
                    │                          └── 无需处理 ──→ CLOSED (3) 已关闭 [终态]
                    │
                    └── 管理员直接关闭 ──→ CLOSED (3) 已关闭 [终态]
```

状态说明：

| 状态码 | 状态名 | 含义                         | 可否流转 |
| ------ | ------ | ---------------------------- | -------- |
| 0      | 待处理 | 用户刚提交，等待管理员查看   | → 1 或 3 |
| 1      | 处理中 | 管理员正在处理               | → 2 或 3 |
| 2      | 已解决 | 问题已修复或建议已采纳/回复  | 终态     |
| 3      | 已关闭 | 重复反馈、无效反馈、无法复现 | 终态     |

## 二、数据库变更

### 2.1 新建 feedback 表

```sql
CREATE TABLE IF NOT EXISTS `feedback` (
    `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '反馈ID',
    `user_id`     BIGINT       NOT NULL COMMENT '提交用户ID',
    `type`        TINYINT      NOT NULL DEFAULT 1 COMMENT '反馈类型: 1=问题反馈, 2=功能建议',
    `title`       VARCHAR(200) NOT NULL COMMENT '反馈标题',
    `content`     VARCHAR(2000) NOT NULL COMMENT '反馈内容',
    `contact`     VARCHAR(100) DEFAULT NULL COMMENT '联系方式(邮箱/手机)',
    `images`      VARCHAR(2000) DEFAULT NULL COMMENT '截图URL列表(JSON数组)',
    `status`      TINYINT      NOT NULL DEFAULT 0 COMMENT '状态: 0=待处理, 1=处理中, 2=已解决, 3=已关闭',
    `admin_reply` VARCHAR(2000) DEFAULT NULL COMMENT '管理员回复内容',
    `admin_id`    BIGINT       DEFAULT NULL COMMENT '处理管理员ID',
    `handle_time` DATETIME     DEFAULT NULL COMMENT '处理时间',
    `create_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '提交时间',
    `update_time` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (`id`),
    KEY `idx_user_id` (`user_id`),
    KEY `idx_status` (`status`),
    KEY `idx_type` (`type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户反馈表';
```

### 3.2 详细接口设计

#### 用户端接口

##### POST `/api/feedback` — 提交反馈

```
Request:
{
  "type": 1,                            // 1=问题反馈, 2=功能建议
  "title": "订单页面加载很慢",           // 必填，≤200字
  "content": "在订单列表页滑动时...",    // 必填，≤2000字
  "contact": "user@example.com",         // 选填
  "images": ["url1.jpg", "url2.jpg"]    // 选填，最多3张
}

Response: { code: 200, message: "反馈已提交" }
```

逻辑：

1. 校验标题非空、内容非空
2. 校验 images ≤ 3 张
3. status = 0 (待处理)，写入数据库
4. 从 UserContext 获取当前用户 ID

##### GET `/api/feedback/my` — 我的反馈列表

```
Query: page, pageSize

Response:
{
  code: 200,
  data: {
    records: [
      {
        id: 1,
        type: 1,
        typeText: "问题反馈",
        title: "订单页面加载很慢",
        content: "在订单列表页滑动时...",
        contact: "user@example.com",
        images: [...],
        status: 0,
        statusText: "待处理",
        adminReply: null,
        handleTime: null,
        createTime: "2026-06-04T10:00:00"
      }
    ],
    total: 1,
    page: 1,
    pageSize: 20
  }
}
```

仅返回当前登录用户的反馈，按 createTime 倒序。

##### GET `/api/feedback/my/{id}` — 我的反馈详情

返回单条反馈完整信息（含管理员回复），校验反馈归属当前用户。

#### 管理后台接口

##### GET `/api/admin/feedbacks` — 反馈列表

```
Query: page, pageSize, type, status, keyword(标题搜索)

Response: PageResult<Feedback>
```

##### GET `/api/admin/feedbacks/{id}` — 反馈详情

返回单条反馈完整信息（含用户信息）。

##### PUT `/api/admin/feedbacks/{id}/reply` — 回复反馈

```
Request:
{
  "status": 1,                        // 处理后的状态: 1=处理中, 2=已解决, 3=已关闭
  "adminReply": "已确认该问题..."      // 管理员回复内容，必填
}

Response: { code: 200, message: "success" }
```

逻辑：

1. 校验 status 在有效范围 (1/2/3)
2. 校验 adminReply 非空
3. 更新 feedback 的状态、回复内容、adminId、handleTime

##### DELETE `/api/admin/feedbacks/{id}` — 删除反馈

硬删除，仅管理员可操作。

### 3.3 Service 核心逻辑伪代码

```java
// FeedbackServiceImpl.submitFeedback - 提交反馈
public void submitFeedback(Long userId, FeedbackSubmitRequest req) {
    Feedback feedback = new Feedback();
    feedback.setUserId(userId);
    feedback.setType(req.getType());
    feedback.setTitle(req.getTitle());
    feedback.setContent(req.getContent());
    feedback.setContact(req.getContact());
    feedback.setImages(req.getImages() != null ? toJson(req.getImages()) : null);
    feedback.setStatus(FeedbackStatus.PENDING);
    feedback.setCreateTime(LocalDateTime.now());
    feedbackMapper.insert(feedback);
}

// FeedbackServiceImpl.replyFeedback - 管理员回复
public void replyFeedback(Long adminId, Long id, FeedbackReplyRequest req) {
    Feedback feedback = feedbackMapper.selectById(id);
    feedback.setStatus(req.getStatus());
    feedback.setAdminReply(req.getAdminReply());
    feedback.setAdminId(adminId);
    feedback.setHandleTime(LocalDateTime.now());
    feedbackMapper.updateById(feedback);
}
```

## 七、路由规划

客户端不新增独立路由 — 反馈功能**内嵌在 `profile.vue` 的 section 切换中**，通过 `currentSection` 控制显示。

管理后台新增一条路由（见 5.3）。

## 九、边界情况与约束

| 场景                               | 处理方式                                              |
| ---------------------------------- | ----------------------------------------------------- |
| 未登录用户访问                     | profile.vue 有 requiresAuth 守卫，自动跳转登录        |
| 空白反馈列表                       | 显示 `el-empty` + "暂无反馈，去提交你的第一条反馈吧"  |
| 提交反馈时重复点击                 | 按钮加 loading 锁                                     |
| 图片超过 3 张                      | 前端 el-upload `:limit="3"` + 后端校验                |
| 图片超过 2MB                       | 前端 `beforeUpload` 校验，同 profile.vue 头像上传逻辑 |
| 联系方式为空                       | 表单默认填入用户邮箱                                  |
| 已关闭/已解决的反馈                | 用户不可再编辑或删除                                  |
| 管理后台删除反馈                   | 硬删除，需二次确认                                    |
| 管理员回复内容为空                 | 后端校验必填                                          |
| 管理员将状态改为"处理中"但未填回复 | adminReply 可为空（仅状态变更时）                     |
