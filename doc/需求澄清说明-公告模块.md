## 二、需要澄清的核心问题

### Q1：公告展示范围

公告条应该在哪里展示？

**方案 A — 仅首页展示（当前实现）**

- 组件放在 `home/index.vue` 中，用户只在首页看到公告
- 优点：改动最小，不干扰其他页面
- 缺点：用户浏览商品详情、下单等页面时看不到公告

**方案 B — 全站横幅（推荐）**

- 组件移到 `DefaultLayout.vue`，在导航栏下方所有页面展示
- 优点：公告触达率高，适合重要通知
- 缺点：需要处理某些页面不需要公告的情况（如登录页、支付页）

> **请选择：** A / B？

| 公告入口（如 footer 链接）      | 从页脚等位置进入公告列表 | 可选 |

- 优点：零额外开发

**方案 B — 添加公告列表页**

- 用户可以浏览所有已发布公告
- 优点：信息留存，不错过已关闭的公告

## 三、建议的最小可行方案（MVP）

综合考虑实验要求和实现成本，建议以下优先修复：

### 必须修复（阻塞性问题）

1. **管理后台公告 CRUD 实现** — `announcement.vue` 补充发布/编辑/删除功能（弹窗式）
2. **管理端 API 封装** — `admin.ts` 添加公告相关 API 调用函数
3. **列表加载** — 修正后台公告列表从后端加载数据（当前用 `ref([])` 初始空数组，根本没调接口）

### 建议修复（功能完善）

4. **添加 `status` 字段** — 支持草稿/发布/下架，用户端仅查已发布
5. **修复 `getLatest` SQL** — 改用 `Page` 分页
6. **公告条关闭行为改进** — 改为"关闭当前条"而非"关闭所有"

### 可选增强

7. 添加 `sort_order` 字段
8. 添加 `level` 字段 + 不同颜色样式
9. 公告条移到 `DefaultLayout` 实现全站展示
10. 富文本编辑器
