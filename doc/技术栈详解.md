# 乐购电商平台 — 技术栈详解

---

## 一、项目总览

本项目是一个**前后端分离的全栈电商平台**，包含三个独立应用：

| 模块 | 说明 | 端口 |
|---|---|---|
| 后端 (Back) | Java Spring Boot REST API | 8080 |
| 前台 (Client) | 面向消费者的商城页面 | 5173 |
| 后台 (Admin) | 面向管理员的管理系统 | 5174 |

此外还有一个 `shared/` 目录存放前后端共享的 TypeScript 类型定义和校验逻辑。

---

## 二、后端技术栈（重点）

### 2.1 核心框架：Spring Boot 3.2.5

**Spring Boot** 是整个后端的基石。它是一个基于 Java 的微框架，通过"自动配置"大幅简化了 Spring 应用的搭建和开发。

在本项目中的作用：
- **启动和运行**：通过内嵌 Tomcat 提供 HTTP 服务，无需单独部署 Web 服务器
- **依赖注入（IoC 容器）**：管理所有对象（Service、Mapper、Interceptor 等）的创建和生命周期，通过 `@Autowired` 自动装配
- **自动配置**：根据 classpath 中的 jar 包自动配置数据源、事务管理、Jackson 序列化等
- **配置管理**：通过 `application.yml` 集中管理数据库连接、端口、JWT 密钥等所有配置项

### 2.2 编程语言：Java 17

本项目使用 **Java 17**（LTS 长期支持版本），支持 record 类型、sealed class、pattern matching、text blocks 等现代语法特性，比 Java 8/11 更简洁高效。

### 2.3 构建工具：Maven

**Maven**（`pom.xml`）负责：
- **依赖管理**：声明式地引入第三方 jar 包（Spring Boot、MyBatis-Plus、JWT 等），Maven 自动解析传递性依赖
- **项目构建**：通过 `mvn compile` / `mvn package` 编译、测试、打包成可运行的 .jar 文件
- **生命周期管理**：clean → compile → test → package 等标准化构建流程

### 2.4 数据库：MySQL 8.0

**MySQL** 是关系型数据库，存储所有业务数据。

在本项目中的具体作用：
- **数据持久化**：用户、商品、订单、购物车、评价等 15 张表的数据存储
- **中文全文搜索**：利用 MySQL 的 `FULLTEXT` 索引 + `ngram` 分词器实现对中文商品名称的全文搜索
- **模糊搜索**：通过 SQL `LIKE` 实现关键词匹配
- **编辑距离算法**：通过自定义 `levenshtein()` 函数，实现输入错误时的容错搜索（编辑距离 ≤ 2）
- **连接配置**：`jdbc:mysql://localhost:3306/ecommerce?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai`

### 2.5 ORM 框架：MyBatis-Plus 3.5.6

**MyBatis-Plus** 是对 MyBatis 的增强，它在保留 MyBatis 原生 SQL 能力的同时，提供了大量开箱即用的便利功能。

在本项目中的具体作用：
- **零 SQL 的 CRUD**：通过继承 `BaseMapper<T>`，自动获得 `insert()`、`deleteById()`、`updateById()`、`selectById()`、`selectList()` 等方法，无需手写基础 SQL
- **分页插件**：通过 `PaginationInnerInterceptor` 自动拦截分页查询，结合 `Page<T>` 对象返回分页结果（总条数、总页数、当前页数据）
- **自动填充**：通过 `MyMetaObjectHandler` 在插入/更新时自动填充 `create_time`、`update_time` 等字段
- **驼峰/下划线自动映射**：数据库字段 `create_time` ↔ Java 实体属性 `createTime` 自动转换
- **Lambda 查询构造器**：支持类型安全的 `LambdaQueryWrapper`，避免字段名写错的魔法字符串问题
- **SQL 日志**：开发阶段通过 `StdOutImpl` 打印 SQL 语句和参数到控制台，方便调试

### 2.6 身份认证：JWT (JSON Web Token)

**JWT**（基于 `jjwt` 库 0.12.5）是前后端分离架构中实现无状态认证的标准方案。

在本项目中的具体作用：
- **登录时签发**：用户/管理员输入账号密码登录成功后，后端生成一个包含用户 ID 和角色的 JWT token 返回给前端
- **请求时携带**：前端将 token 存在 `localStorage`，之后每次请求都在 HTTP Header 中带上 `Authorization: Bearer <token>`
- **拦截器验证**：
  - `LoginInterceptor`：拦截 `/api/user/**`、`/api/cart/**` 等消费者接口，解析 token、校验签名，把用户 ID 存入 `UserContext`（ThreadLocal）
  - `AdminInterceptor`：拦截 `/api/admin/**` 管理后台接口，额外校验是否为管理员角色
- **无状态**：服务端不存 session，水平扩展时无需共享 session 存储
- **过期时间**：7 天（604800000ms），到期后需重新登录
- **密码加密**：用户密码通过 **BCrypt**（`spring-security-crypto`）进行哈希存储，不可逆，登录时用 `BCryptPasswordEncoder.matches()` 比对明文和密文

**需要注意**：本项目并未引入完整的 Spring Security 框架，仅仅引用了 `spring-security-crypto` 这个独立库来使用 BCrypt。认证逻辑是自己通过拦截器手写的。

### 2.7 简化代码：Lombok 1.18.36

**Lombok** 是一个编译期注解处理器，自动生成样板代码。

在本项目中的具体作用：
- `@Data`：生成 getter/setter/toString/equals/hashCode
- `@NoArgsConstructor` / `@AllArgsConstructor`：生成无参/全参构造函数
- `@Builder`：生成建造者模式的 builder 类
- `@Slf4j`：注入日志对象
- 显著减少 Entity、DTO 等类的手写代码量

### 2.8 参数校验：Bean Validation

**spring-boot-starter-validation** 提供声明式参数校验。

在本项目中的具体作用：
- 通过 `@NotNull`、`@NotBlank`、`@Size`、`@Min`、`@Max`、`@Email` 等注解在 DTO 字段上声明校验规则
- 在 Controller 方法参数前加 `@Valid` 即可自动触发校验
- 校验失败时抛出 `MethodArgumentNotValidException`，由 `GlobalExceptionHandler` 统一捕获并返回友好的错误信息

### 2.9 统一响应 & 异常处理

本项目自己封装了两个基础设施：

**`Result<T>` — 统一 API 响应格式：**
```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```
所有 Controller 返回值都包装在 `Result` 中，前端可以统一处理成功和失败两种情况。

**`GlobalExceptionHandler` — 全局异常处理：**
- 通过 `@ControllerAdvice` 拦截所有未捕获的异常
- `BusinessException`（自定义业务异常）→ 返回具体的业务错误码和提示
- 校验异常 → 返回参数不合法提示
- 其他未知异常 → 返回 500 服务器内部错误
- 避免将异常堆栈直接暴露给前端

### 2.10 跨域配置：CORS

在 `WebMvcConfig` 中配置全局 CORS，允许任意来源的跨域请求，支持 GET/POST/PUT/DELETE/OPTIONS 方法，允许携带 Cookie（credentials）。

### 2.11 文件上传

- **存储方式**：本地文件系统，路径为项目根目录的 `./upload/`
- **大小限制**：单文件最大 2MB，单次请求最大 10MB
- **格式限制**：仅允许 `jpg, jpeg, png, gif, webp`
- **静态资源访问**：通过 `WebMvcConfig` 将 `/upload/**` URL 映射到本地 `./upload/` 目录，上传后的图片可直接通过 URL 访问

### 2.12 支付（模拟）

支付流程采用**完全模拟**的方式，未接入真实支付网关（微信/支付宝等）。

- `PaymentSession` 实体记录支付意图
- `OrderService` 中的支付逻辑为本地状态变更
- 前台支付页面有倒计时功能，超时自动取消订单并恢复库存

## 三、后端架构分层

后端采用经典的**三层架构 + MVC 模式**：

```
┌─────────────────────────────────────────┐
│  Controller 层（接口层）                  │
│  - 接收 HTTP 请求                         │
│  - 参数校验 (@Valid)                      │
│  - 调用 Service                           │
│  - 返回 Result<T> 统一响应                 │
├─────────────────────────────────────────┤
│  Interceptor 层（拦截器）                  │
│  - JWT 认证 & 授权                        │
│  - 用户上下文注入 (ThreadLocal)            │
├─────────────────────────────────────────┤
│  Service 层（业务逻辑层）                   │
│  - 核心业务逻辑                            │
│  - 事务管理 (@Transactional)               │
│  - 调用 Mapper                            │
│  - 抛出 BusinessException                 │
├─────────────────────────────────────────┤
│  Mapper 层（数据访问层）                    │
│  - MyBatis-Plus BaseMapper CRUD          │
│  - 自定义 SQL (XML 或注解)                 │
│  - 分页查询                                │
├─────────────────────────────────────────┤
│  Entity / DTO 层（数据模型）               │
│  - Entity: 数据库表映射                    │
│  - DTO: 前后端数据传输对象                  │
├─────────────────────────────────────────┤
│  Config 层（配置）                         │
│  - MyBatis-Plus 分页插件配置               │
│  - WebMvc CORS + 拦截器 + 静态资源         │
│  - 全局异常处理                            │
└─────────────────────────────────────────┘
```

**各层之间的数据流**：
1. 请求 → `WebMvcConfig` 注册的 `LoginInterceptor`/`AdminInterceptor` 验证 JWT
2. 通过后进入 Controller，进行参数校验
3. Controller 调用 Service 执行业务逻辑
4. Service 调用 Mapper 操作数据库
5. 返回结果经 Controller 包装成 `Result<T>` 后序列化为 JSON 响应

## 四、前端技术栈

### 4.1 核心框架：Vue 3

**Vue 3**（Composition API + `<script setup>` 语法糖）是前端的主要框架。

作用：
- **组件化开发**：页面拆分为可复用的 `.vue` 单文件组件（template + script + style）
- **响应式系统**：通过 `ref()` / `reactive()` 实现数据变化自动更新 DOM
- **Composition API**：通过 `composables/` 目录封装可复用的逻辑（如 `usePagination`、`useSearchHistory`）
- **`<script setup>`**：更简洁的语法，无需手动 `defineComponent` 和 `return`

### 4.2 状态管理：Pinia

**Pinia** 是 Vue 3 官方推荐的状态管理库，替代 Vuex。

在本项目中的作用：
- `stores/cart.ts`：管理购物车数据（添加、修改数量、勾选、清空），全局共享
- `stores/user.ts`：管理用户登录状态、token、个人信息
- `stores/admin.ts`：管理后台管理员登录状态

### 4.3 前端路由：Vue Router 4

**Vue Router** 负责前端页面的路由导航。

在本项目中的作用：
- 定义 URL 与页面组件的映射关系（如 `/product/:id` → 商品详情页）
- 路由守卫（`beforeEach`）：未登录用户访问需要登录的页面时自动跳转到登录页
- 布局切换：默认页面使用 `DefaultLayout`（含头部导航和底部），登录/注册页使用 `BlankLayout`（空白布局）

### 4.4 HTTP 客户端：Axios

**Axios** 是前端发送 HTTP 请求的库。

在本项目中的作用：
- 封装 `request.ts`：创建 Axios 实例，配置 baseURL、超时时间
- **请求拦截器**：自动在每个请求的 Header 中附带 JWT token（从 localStorage 读取），以及 Content-Type
- **响应拦截器**：统一处理错误（401 未登录跳转登录页，500 显示错误提示）
- 返回类型泛型支持（`request.get<Result<Product[]>>(...)`）

### 4.5 UI 组件库：Element Plus

**Element Plus**（`element-plus` 2.6+）是 Vue 3 生态中最主流的桌面端 UI 组件库。

在本项目中的具体作用：
- **表单**：`el-form` / `el-input` / `el-select` / `el-upload` — 登录、注册、商品编辑等所有表单
- **表格**：`el-table` — 后台管理的用户列表、商品列表、订单列表
- **布局**：`el-container` / `el-header` / `el-main` / `el-footer` — 后台管理布局
- **导航**：`el-menu` / `el-breadcrumb` / `el-tabs` — 导航菜单和面包屑
- **反馈**：`el-message` / `el-dialog` / `el-loading` / `el-popconfirm` — 消息提示、弹窗、加载状态
- **数据展示**：`el-pagination` / `el-tag` / `el-image` / `el-card` / `el-empty` / `el-badge` — 分页、标签、图片、卡片等
- **图标**：`@element-plus/icons-vue` — 购物车图标、用户图标、搜索图标等
- **级联选择器**：`el-cascader` — 商品分类选择（树形层级结构）

### 4.6 CSS 预处理：Sass (SCSS)

**Sass** 提供 CSS 预处理能力（变量、嵌套、mixin、函数等），通过 `global.scss` 定义全局样式、主题色、覆盖 Element Plus 默认样式。

### 4.7 后台图表：ECharts 5.5

**ECharts** 仅在后台管理系统的 Dashboard 页面使用，用于绘制销售趋势折线图、订单统计柱状图等数据可视化图表。

### 4.8 组合式工具：VueUse

**@vueuse/core** 是一个 Vue Composition API 工具集，提供 `useLocalStorage`、`useDebounce`、`useTitle` 等开箱即用的组合式函数，减少重复的底层逻辑编写。

### 4.9 构建工具：Vite 5

**Vite** 是新一代前端构建工具，基于 ES Module 原生导入。

在本项目中的作用：
- **开发服务器**：启动毫秒级的热更新开发服务器（端口 5173/5174）
- **API 代理**：开发时将 `/api` 请求代理到 `http://localhost:8080`，解决跨域问题
- **生产构建**：通过 Rollup 打包，输出优化后的静态文件

### 4.10 类型系统：TypeScript 5.4

**TypeScript** 为 JavaScript 添加静态类型检查。

在本项目中的作用：
- 类型定义（`shared/types/`）：定义 `Product`、`Order`、`User`、`ApiResponse<T>` 等接口
- IDE 智能提示：编码时的自动补全和参数提示
- 编译时错误检查：`vue-tsc` 在构建前检查类型错误，避免运行时 bug
- 前后端类型共享：`shared/` 目录下的类型被前台和后台共同引用，保持一致性

## 六、项目未引入的技术（说明）

以下技术在更复杂的电商项目中常见，但**本项目未引入**，这有助于理解项目的定位和复杂度：

| 未引入的技术 | 说明 |
|---|---|
| **Spring Security** | 未使用完整的 Spring Security 框架，认证是通过手写拦截器 + JWT 实现的，更轻量但也更简单 |
| **Redis** | 无缓存层，所有查询直接访问 MySQL。电商中常用 Redis 缓存热门商品、存储购物车、分布式锁等 |
| **消息队列** | 无 MQ（RabbitMQ/Kafka），订单创建、库存扣减等都是同步操作。真实电商会用 MQ 异步处理下单、发短信等 |
| **Elasticsearch** | 无专业搜索引擎，商品搜索全靠 MySQL FULLTEXT + LIKE + Levenshtein，数据量大时性能瓶颈明显 |
| **Docker** | 无容器化部署，所有服务本地直接运行 |
| **微服务** | 单体架构，所有功能在一个 Spring Boot 应用中，没有拆分为多个微服务 |
| **真实支付** | 支付为纯模拟流程，未对接微信支付/支付宝 API |
| **WebSocket** | 无实时通信，订单状态变化需要手动刷新页面 |
