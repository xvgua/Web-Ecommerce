## 二、已实现功能详细分析

### 2.1 用户注册

**后端** (`UserServiceImpl.register`)：
- 校验 `password == confirmPassword`
- Redis 验证码校验（`VerificationCodeService.verify`）
- 用户名/邮箱唯一性检查
- 生成 8 位账号 ID（YYMMDDNN 格式，每日上限 99）
- BCrypt 密码加密
- 默认 `nickname = username`，`status = ACTIVE`

**前端** (`register.vue`)：
- 5 字段表单：用户名、邮箱、验证码、密码、确认密码
- 60 秒发送冷却倒计时
- 邮箱变更时自动重置验证码和冷却
- 前端表单校验 + 后端 `@Valid` 双重校验

**结论：** 注册流程完整，校验充分。

### 2.2 验证码系统

**后端** (`VerificationCodeServiceImpl`)：
- Redis 存储，key 前缀 `register:code:<email>`，TTL 5 分钟
- 60 秒发送冷却（`register:cooldown:<email>`）
- 最多 5 次验证尝试（`register:attempts:<email>`）
- 6 位安全随机数生成（`SecureRandom`）
- 163 邮箱 SMTP 发送 HTML 邮件
- 邮件不可用时 fallback 到日志输出（不阻塞启动）

**前端** (`register.vue`)：
- 发送按钮含 loading 状态 + 倒计时
- `captchaRules`：必填、6 位数字格式校验

**结论：** 验证码机制完善，有防刷保护。

### 2.3 账号密码登录

**后端** (`UserServiceImpl.login`)：
- 用户名查找 → 检查禁用状态 → BCrypt 密码比对
- 统一错误提示（不区分用户不存在/密码错误，防枚举）
- 返回 JWT token + 用户信息（密码已置空）

**前端** (`login.vue`)：
- 用户名 + 密码表单
- 登录成功后跳转首页，失败由拦截器提示

**结论：** 登录流程安全，错误提示遵循最佳实践。

### 2.4 记住密码

**后端** (`JwtUtils.generateToken`)：
- `remember=true` 时 JWT 过期时间延长 4 倍（7天 → 28天）

**前端**：
- `login.vue` 有 `remember` 复选框，随登录请求发送
- 但**前端未在 localStorage 保存用户名/密码**，下次访问仍需手动输入
- token 持久化在 `localStorage`（`ECOMMERCE_TOKEN`），页面刷新后保持登录

**结论：** 后端 JWT 延长已实现，但前端缺少凭据记忆功能。

### 2.5 退出登录

**后端**：无状态 JWT，无需服务端注销。

**前端** (`userStore.logout`)：
- 清除 `token`、`user` 状态
- 移除 `localStorage` 中 `TOKEN_KEY`、`USER_KEY`
- 导航回首页

**结论：** 退出登录实现正确。

## 三、缺失功能分析

### 3.1 找回密码 — **完全缺失**

| 层级 | 缺失项 |
|------|--------|
| 后端 | 无 `/api/auth/reset-password` 或类似端点 |
| 后端 | 无 `reset-password` 验证码类型 |
| 后端 | 无密码重置服务方法 |
| 前端 | `login.vue` 第 50 行："忘记密码？" 链接为 `href="javascript:void(0)"` — 死链接 |
| 前端 | 无找回密码页面/弹窗 |
| 前端 | 无重置密码 API 调用 |

**需要实现：**
1. 后端：`POST /api/auth/send-reset-code` — 发送重置密码验证码到邮箱
2. 后端：`POST /api/auth/reset-password` — 验证码 + 新密码
3. 前端：找回密码页面/弹窗（邮箱输入 → 验证码 → 新密码）
4. `VerificationCodeService` 需支持 `reset` 类型的验证码

### 3.2 修改密码 — **界面存在但功能缺失**

- `profile.vue` 第 88 行有"修改密码"按钮
- 第 107 行声明了 `showPwdDialog = ref(false)`
- 但**没有对应的对话框组件、API 调用或后端端点**
- `PUT /api/user/info` 不处理密码字段

### 3.3 路由导航守卫 — **缺失**

- 路由定义中有 `meta: { requiresAuth: true }` 标记
- 但 `router/index.ts` **没有 `beforeEach` 守卫**
- 未登录用户可以直接访问 `/cart`、`/orders` 等受保护页面
- 鉴权完全依赖 API 层的 Axios 401 拦截器做被动跳转
- 页面级的未授权访问无法在路由层面阻止

### 3.4 记住密码前端持久化 — **部分缺失**

- 登录表单有"记住密码"复选框
- 但关闭浏览器后重新打开，**用户名和密码输入框为空**
- 仅 token 被持久化，凭据本身未被记忆

## 四、数据持久化审查

### 4.1 数据库 Schema（User 表）

```sql
CREATE TABLE `user` (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  account_id  BIGINT       NOT NULL UNIQUE,
  username    VARCHAR(50)  NOT NULL UNIQUE,
  password    VARCHAR(255) NOT NULL,        -- BCrypt 哈希
  email       VARCHAR(100) NOT NULL,        -- 注册时写入，无 verified 标记
  nickname    VARCHAR(50)  DEFAULT '',       -- 注册时默认=username
  avatar      VARCHAR(500) DEFAULT '',
  phone       VARCHAR(20)  DEFAULT '',
  gender      TINYINT      DEFAULT 0,       -- 0=保密 1=男 2=女
  intro       VARCHAR(255) DEFAULT '',
  username_update_time DATETIME NULL,
  status      TINYINT      DEFAULT 1,       -- 1=启用 0=禁用
  create_time DATETIME     DEFAULT CURRENT_TIMESTAMP,
  update_time DATETIME     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 4.2 各数据项持久化状态

| 数据项 | DB 持久化 | 前端持久化 | 备注 |
|--------|----------|-----------|------|
| 邮箱 | `user.email` (NOT NULL) | 无 | 注册写入，无 verified 标记 |
| 密码 | `user.password` (BCrypt) | 无 | 加密存储 ✓ |
| 昵称 | `user.nickname` | 无 | 注册默认=用户名，个人中心可改 |
| Token | 无（JWT 无状态） | `localStorage.ECOMMERCE_TOKEN` | 关闭浏览器后仍保持 |
| 用户信息 | `user` 表全字段 | `localStorage.ECOMMERCE_USER` (JSON) | 刷新后可恢复 |
| 用户名 | `user.username` (UNIQUE) | 无 | 注册后不可修改（月改限制在 profile 中） |

### 4.3 持久化问题

1. **邮箱未验证标记** — `email` 字段无 `email_verified` 列。验证码仅用于注册流程，注册后无"已验证"标记。
2. **前端记住密码不完整** — "记住密码"复选框仅影响 JWT 过期时长，未在客户端保存凭据。
3. **localStorage 存储用户对象** — 敏感信息（用户名、邮箱、电话）以明文 JSON 存储在 localStorage，存在 XSS 泄露风险。

## 五、安全性评估

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 密码 BCrypt 加密 | 通过 | `BCryptPasswordEncoder` |
| 统一错误提示 | 通过 | 不区分用户不存在/密码错误 |
| SQL 参数化 | 通过 | MyBatis-Plus `#{}` |
| 验证码防刷 | 通过 | 60s 冷却 + 5 次重试上限 |
| JWT 签名 | 通过 | HMAC-SHA 签名 |
| 用户隔离 | 通过 | ThreadLocal `UserContext` |
| 401 自动清除 token | 通过 | Axios 拦截器处理 |
| 路由守卫 | **缺失** | 页面级保护不完整 |
| 邮箱已验证标记 | **缺失** | 注册后无状态区分 |
| XSS 防护 | 一般 | localStorage 存储用户数据 |

## 六、修复优先级建议

### 高优先级（核心功能缺失）

1. **实现找回密码** — 完整的前后端流程
   - 后端：`POST /api/auth/send-reset-code` + `POST /api/auth/reset-password`
   - 前端：找回密码页面/弹窗
   - 复用现有验证码基础设施

2. **实现路由导航守卫** — `router.beforeEach` 检查 token
   - 未登录访问受保护页面 → 重定向 `/login`
   - 已登录访问 `/login` → 重定向 `/`

3. **实现修改密码** — 补充 `profile.vue` 中缺失的弹窗和后端端点
   - 后端：`PUT /api/user/password` (旧密码 + 新密码)
   - 前端：修改密码弹窗组件

### 中优先级（体验改进）

4. **完善记住密码** — 前端可选保存用户名到 localStorage
5. **邮箱验证状态** — 可选：添加 `email_verified` 字段

### 低优先级（加固）

6. **敏感数据加密** — 考虑不在 localStorage 明文存储用户对象
7. **Token 刷新机制** — 考虑 refresh token 模式
