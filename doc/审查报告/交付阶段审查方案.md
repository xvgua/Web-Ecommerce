| # | 子项 | 状态 | 实现位置 | 审查要点 |

| 2 | 权限验证 | ✅ 已实现 | `AdminInterceptor.java` — 校验 JWT + 检查 `role` 声名为 `ADMIN` 或 `SUPER_ADMIN`；`WebMvcConfig.java` 将拦截器应用于 `/api/admin/**` | 验证非管理员 token 访问返回 403 |
| 3 | 管理员退出 | ✅ 已实现 | 前端 `adminStore.logout()` 清除 token + username；无状态 JWT 无需服务端注销 | 验证退出后访问后台重定向登录页 |
| 4 | 角色管理 | ⚠️ 基础实现 | `Admin` 实体含 `role` 字段（`ADMIN` / `SUPER_ADMIN`），但无角色管理 UI、无权限分级管理页面、前端不区分角色功能 | 此为可选需求。当前满足基本权限区分，缺少可视化角色管理 |

**潜在风险：**
- 管理端路由无前端导航守卫（`router/index.ts` 无 `beforeEach`），依赖 API 层 401/403 拦截被动跳转。
- `admin.ts` API 类型声明仅含 5 个字段（`totalUsers`, `totalOrders`, `totalSales`, `todayOrders`, `todaySales`），但后端实际返回 9 个字段（含 4 个订单状态计数）。类型定义与后端响应不一致，但不影响运行时功能。

> 3.3 容器化部署：基于 Docker 容器封装项目运行环境，统一开发、测试、生产环境配置，保障多环境部署一致性。
