# 商品上架时间功能审查报告

## 一、问题分析

### 1.1 现状

当前系统通过 `product.create_time`（数据库记录创建时间）来区分"新品"：

| 位置 | 当前行为 | 问题 |
|------|----------|------|
| `Back/init.sql:66` | `create_time DATETIME DEFAULT CURRENT_TIMESTAMP` | 所有商品批量 INSERT 时 time 相同，无法区分先后 |
| `ProductServiceImpl:getNewProducts()` | `ORDER BY create_time DESC` | 排序依据只有一个字段 |
| `ProductServiceImpl:applySort()` | `newest` 排序 = `createTime DESC` | 同上 |
| `ProductCard.vue:32-35` | `Date.now() - createTime < 7天` → 显示 NEW 角标 | 角标逻辑依赖于 create_time |
| `ProductForm` | 无任何时间字段 | 管理员创建/编辑时无法指定上架时间 |

**核心矛盾：** `create_time` 是"数据库记录的创建时间"，不是"商品上架售卖的时间"。当管理员先保存为下架草稿、稍后再上架时，`create_time` 实际上是草稿创建时间。

### 1.2 需求目标

为每个商品增加明确的"上架时间"（首次从上架/下架状态变为上架的时间点），用于：

1. 首页「新品推荐」准确排序 — 按上架时间 DESC
2. 商品卡片「NEW」角标 — 基于上架时间判断是否新品（如 7 天内）
3. 商品列表「最新上架」排序 — 按上架时间 DESC
4. 管理后台可见/可管理（可选）

## 二、需修改的模块

### 2.1 数据库（`Back/init.sql`）

| 文件 | 修改内容 |
|------|----------|
| `init.sql` — `product` 表 | 新增 `listed_at DATETIME DEFAULT NULL COMMENT '首次上架时间'` 列 |
| 数据迁移 SQL | 为已有上架商品（status=1）批量填充 `listed_at = create_time` |

**DDL 参考：**

```sql
ALTER TABLE product ADD COLUMN listed_at DATETIME DEFAULT NULL COMMENT '首次上架时间';

-- 为现有上架商品回填
UPDATE product SET listed_at = create_time WHERE status = 1 AND listed_at IS NULL;
```

### 2.2 后端实体层

| 文件 | 修改内容 |
|------|----------|
| `entity/Product.java` | 新增 `private LocalDateTime listedAt` 字段 |

无 MyBatis-Plus 自动填充注解（需手动控制赋值时机）。

### 2.3 后端 DTO 层

| 文件 | 修改内容 |
|------|----------|
| `dto/ProductForm.java` | 无需修改 — 上架时间由后端自动管理，不应由前端传入（安全考虑） |

### 2.4 后端 Service 层（核心逻辑）

| 文件 | 方法 | 修改内容 |
|------|------|----------|
| `service/impl/ProductServiceImpl.java` | `getNewProducts()` | 排序改为 `listedAt DESC` |
| 同上 | `applySort()` | `newest` 分支改为 `listedAt DESC` |
| 同上 | `create()` | 新建商品时若 `status == 1`（上架），设置 `listedAt = LocalDateTime.now()` |
| 同上 | `update()` | 编辑商品时若 `status` 从上架/下架变为上架，且 `listedAt` 为空，设置 `listedAt = LocalDateTime.now()` |
| 同上 | `syncProductFromSkus()` | 无需修改 |
| 同上 | `createDefaultSku()` | 无需修改 |

**关键逻辑规约：**

```
创建商品:
  if status == 上架 → listedAt = now()
  if status == 下架 → listedAt = null

更新商品:
  if 新status == 上架 AND 原status != 上架 AND listedAt == null
    → listedAt = now()  // 首次上架，记录时间
  if 新status == 上架 AND listedAt != null
    → 保持不变           // 已经上架过，不改时间
  if 新status == 下架
    → 保持不变           // 下架不改变上架时间，保留历史
```

## 四、规约

### 4.1 命名规约

| 层 | 命名 | 格式 |
|----|------|------|
| 数据库列 | `listed_at` | snake_case |
| Java 实体 | `listedAt` | camelCase |
| Java getter/setter | `getListedAt()` / `setListedAt()` | Lombok 自动生成 |
| TypeScript | `listedAt` | camelCase，类型 `string \| undefined` |
| 中文展示 | "上架时间" / "首次上架" | — |

### 4.2 行为规约

1. **上架时间只设置一次** — `listedAt` 记录的是商品首次从上架状态变为上架的时间，之后再次下架→上架不更新
2. **下架不清除** — 商品下架时保留 `listedAt` 值，方便后续分析
3. **后端计算，前端只读** — 前端不可通过 API 传入 `listedAt`，全部由后端 Service 层根据状态变更自动赋值
4. **新建即上架** — 创建时 status=1 则 `listedAt = now()`；创建时 status=0 则 `listedAt = null`
5. **兼容历史数据** — 存量商品通过 SQL 迁移将 `listed_at` 回填为 `create_time`（假设历史商品创建即上架）
6. **新品定义** — 前端 `isNew` 判断使用 `listedAt`（而非 `createTime`），默认阈值 7 天

### 4.3 排序列替换

| 旧排序列 | 新排序列 | 说明 |
|----------|----------|------|
| `create_time DESC`（新品推荐） | `listed_at DESC` | `getNewProducts()` |
| `create_time DESC`（最新上架排序） | `listed_at DESC` | `applySort("newest")` |

`create_time` 保留原来用途：MyBatis-Plus 自动填充，用于审计/调试。

### 4.4 不需要修改的模块

- **购物车模块** — 不涉及时间
- **订单模块** — 不涉及商品上架时间
- **支付模块** — 不涉及
- **收藏模块** — 不涉及
- **评价模块** — 不涉及
- **分类模块** — 不涉及
- **用户模块** — 不涉及
- **JWT / 安全模块** — 不涉及
- **文件上传** — 不涉及
