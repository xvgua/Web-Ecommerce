### 修改 5 — "待评价"商品的"评价"按钮修正

**文件**: `list.vue` 第 61 行

**当前问题**：
```html
<!-- 第 61 行 — 点"评价"跳转到订单详情，而不是评价页面 -->
<el-button v-if="activeTab === 'review'" type="warning" size="small"
  @click="$router.push(`/orders/${order.id}`)">评价</el-button>
```

这会导致：用户在"待评价"tab 点"评价"，进入的是订单详情页而非评价表单页。

**目标**：评价按钮应针对每个未评价的 `OrderItem` 单独跳转。

有两种方案可选：

**方案 A — 订单级按钮（简单，推荐先采用）**：
点"评价"跳转到订单详情页，在订单详情页中逐商品进行评价（当前 `detail.vue` 第 54-58 行已按商品展示"评价"按钮）。订单列表页仅展示是否有待评价商品。

```html
<el-button v-if="activeTab === 'review' && reviewSubTab === 'pending'"
  type="warning" size="small"
  @click="$router.push(`/orders/${order.id}`)">评价</el-button>
```

这样列表页的"评价"跳转到详情页，详情页中每个未评价的商品行单独有"评价"按钮 → 跳转 `/orders/:orderId/review/:productId`。**当前详情页已实现此逻辑**（detail.vue:54-58）。

**方案 B — 商品级按钮（更贴合淘宝交互）**：
在订单列表卡片中为每个 `OrderItem` 行末显示独立的"评价"按钮，直接跳转评价表单页。改动量大，涉及订单卡片的商品列表布局调整。

**建议**：先采用方案 A，因为订单详情页已有按商品分列的"评价"按钮。

### 修改 6 — "已评价"商品增加"追加评价"按钮

**文件**: `list.vue` + `detail.vue` + `api/product.ts`

**当前问题**：已评价的商品缺少"追加评价"入口。

**目标**：

1. **类型层** (`shared/types/order.ts`) — `OrderItem` 增加字段：

```ts
export interface OrderItem {
  // …现有字段…
  isReviewed?: boolean
  hasFollowUp?: boolean   // 新增：是否已追加评价
}
```

2. **API 层** (`api/product.ts`) — 新增追加评价接口：

```ts
export function createFollowUpReview(data: {
  productId: number
  orderId: number
  rating: number
  content: string
  images: string[]
}): Promise<ApiResponse<Review>> {
  return request.post(`/reviews/${data.productId}/followup`, data)
}
```

3. **订单详情页** (`detail.vue`) — 商品行增加"追加评价"按钮：

```html
<!-- detail.vue 第 54-58 行附近，在已有"评价"按钮后增加 -->
<div class="product-item__action" v-if="order.status === 3 && item.isReviewed">
  <el-button size="small" type="warning" @click.stop="$router.push(`/orders/${order.id}/review/${item.productId}?followUp=1`)">
    追加评价
  </el-button>
</div>
```

4. **评价页面** (`review.vue`) — 适配"追加评价"模式：
   - 读取路由 query `followUp` 参数，若为 `1` 则在标题、API 调用处切换为追加评价逻辑
   - 追加评价可不强制要求评分（仅追加文字/图片），也可要求评分，视产品需求而定

5. **订单列表页** (`list.vue`) — 评价 tab 的"已评价"子 tab 下显示"追加评价"按钮：

```html
<el-button v-if="activeTab === 'review' && reviewSubTab === 'reviewed'"
  type="warning" size="small"
  @click="$router.push(`/orders/${order.id}`)">追加评价</el-button>
```

### 修改 7 — 操作按钮仅在对应状态 tab 下出现

**文件**: `list.vue` 第 57-63 行

**当前问题**：按钮只通过 `order.status` 判断显隐。在"全部"tab 下，不同状态的订单混在一起，各状态按钮都会出现，这本身是正确的。但在特定状态 tab（如"待发货"）下按钮也应正确显示。

**检查点**：确认各 tab 与按钮的对应关系：

| Tab | 应出现按钮 |
|-----|----------|
| 全部 | 所有按钮按各自 status 展示 |
| 待付款 | 去支付、取消 |
| 待发货 | 催发货、修改地址 |
| 待收货 | 查看物流、确认收货 |
| 已完成 | 仅详情 |
| 已取消 | 仅详情 |
| 评价/待评价 | 评价 |
| 评价/已评价 | 追加评价 |

当前代码用 `v-if="order.status === N"` 控制按钮，在"全部"tab 下各状态按钮都会出现，符合预期。在特定 tab 下，由于已按 status 筛选了订单列表，按钮也只展示对应状态的按钮，逻辑上也是正确的。
